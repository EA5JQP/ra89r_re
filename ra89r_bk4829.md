# BK4829 RF transceiver

**Status: identified, its boot configuration extracted, and a driver written —
branch `driver/bk4829`, committed but not yet validated on the radio.**

The radio carries **two** BK481x transceivers.  This is the one on chip select
`PB8`; its sibling is the BK4815 on `PB13` (`ra89r_bk4815.md`).  The bus they
share, the boot bring-up order and the power path are in `ra89r_rfpath.md`.

## Identity and wiring

| | |
|---|---|
| chip select | `PB8` — GPIOB mask `0x100`, active low |
| clock | `PA12` (shared with the BK4815) |
| data | `PB12` (shared, bidirectional: driven to send, released to read) |
| register 0 | reads **`0x4829`** |

`FUN_08009772` is the stock's own identity check: it reads register 0 over this
chip's read path and returns true only for `0x4829`.  When it fails the stock
calls `FUN_08015D14(0x0b)`, which draws error string #11 — the UI's
`4829 Error` (`0x08027118`).

Framing: `reg & 0x7f` to write, `reg | 0x80` to read, then one 16-bit word MSB
first.  The register layer is `FUN_080220A0(value, reg)` for writes and
`FUN_080180F0(reg)` for reads; both bracket the transfer with `PB8` low, and the
bits go out through `FUN_08017D6C`/`FUN_08017FE4` on `PA12`/`PB12`
(`ra89r_rfpath.md` has the timing and the direction switching).

## The boot configuration — `FUN_08006B78`, 39 writes

```
reg 00 = 0x8000    reg 2f = 0x9890    reg 48 = 0xb386
reg 00 = 0x0000    reg 3a = 0x9a7c    reg 49 = 0x2a32
reg 37 = 0x9d1f    reg 3e = 0x94c6    reg 4a = 0x5430
reg 13 = 0x03df    reg 3f = 0x07fe    reg 4d = 0xa015
reg 12 = 0x03db    reg 40 = 0x34f0    reg 4e = 0x6f10
reg 11 = 0x033a    reg 46 = 0x6050    reg 4f = 0x2a28
reg 10 = 0x0318                       reg 53 = 0x2028
reg 14 = 0x0210                       reg 73 = 0x6681
reg 19 = 0x1041                       reg 77 = 0x88ef
reg 1c = 0x0422                       reg 7b = 0x73dc
reg 1d = 0x2aab                       reg 7d = 0xe920
reg 1e = 0x4c58                       reg 7e = 0x303e
reg 1f = 0x165a                       reg 4c = 0xe520
reg 25 = 0x6dba    -- then FUN_0801BAF4() is called --
reg 28 = 0x0b40                       reg 48 = 0xb3b5   (rewritten)
reg 29 = 0xaa00                       reg 47 = 0x6042   (last write)
reg 2a = 0x6600
reg 2c = 0x0022
```

Order matters: the first two writes go to register 0 (`0x8000` then `0x0000`),
the middle block runs in the order shown, and the last two (`0x48`, `0x47`) come
after `FUN_0801BAF4`.

**`FUN_0801BAF4` identified** — the mid-sequence call is a per-build tweak of
register `0x7d`: it reads a three-valued field at `0x20009f37` and, when the flag
at `0x20000301` is 1, writes `0xe940 | (((field - 3) * 3) + 0x0c)`.  The driver
records the position but deliberately does not reproduce the conditional
re-write; `0xe920` above is what this image writes unconditionally.

## How this differs from the UV-K1/K5V3 driver

The K1 tree has both `bk4819.c` and `bk4829.c`, and its own two inits differ:

| reg | K1 `bk4819.c` | K1 `bk4829.c` |
|---|---|---|
| `0x37` | `0x1D0F` | `0x9D1F` |
| `0x7D` | `0xE940` | `0xE920` |
| `0x1F` | `0x5454` | `0xC65A` |
| `0x3E` | `0xA037` | `0x94C6` |

and the K1's BK4829 init carries a block the BK4819's does not: `0x1C`, `0x1D`,
`0x1E`, `0x73`, `0x77`, `0x28`, `0x29`, `0x2A`, `0x2C`, `0x2F`, `0x53`, `0x7E`,
`0x46`, `0x4A`, `0x07`.

This radio's BK4829 against the K1's BK4829 — same chip, two boards.  Identical:
`0x00` ×2, `0x10`–`0x14`, `0x19`, `0x1E`, `0x28`, `0x29`, `0x2A`, `0x2F`, `0x37`,
`0x3E`, `0x4A`, `0x53`, `0x77`, `0x7B`, `0x7D`, `0x7E`.  Different:

| reg | this radio | K1 |
|---|---|---|
| `0x1C` | `0x0422` | `0x07C0` |
| `0x1D` | `0x2AAB` | `0xE555` |
| `0x1F` | `0x165A` | `0xC65A` |
| `0x2C` | `0x0022` | `0x1822` |
| `0x3F` | `0x07FE` | `0x0000` |
| `0x40` | `0x34F0` | `0x3516` |
| `0x46` | `0x6050` | `0x600A` |
| `0x48` | `0xB386` → `0xB3B5` | `0x33A8` |
| `0x49` | `0x2A32` | `0x2AB2` |
| `0x73` | `0x6681` | `0x4691` |

This radio also writes seven registers the K1's init never touches: `0x25`,
`0x3A`, `0x4C`, `0x4D`, `0x4E`, `0x4F`, `0x47`; and the K1 writes `0x36` where
this radio writes `0x2C`.

## The driver

`firmware/App/driver/bk4829.c` / `.h` on branch `driver/bk4829`, modelled on the
K1's driver layout with this board's pins.  It carries the 39 writes above as a
table and exposes `bk4829_init`, `bk4829_detect`, `bk4829_read_reg`,
`bk4829_write_reg`, `bk4829_configure`.  The console gains `R` (read the id — the
stock's own check) and `W` (replay the configuration and re-read the id, so a
silent bus and a configured chip look different).

Not validated on the radio: `R` has not been run and `W` has not been exercised,
so the branch stays unmerged.

## Other configuration in the same image

The boot init is not the whole story; the per-band, mode and RX/TX setup live in
other routines, ranked by how many registers each writes:

* `FUN_0801740C` (18 writes), `FUN_08017280` (7), `FUN_08016DE8` (6),
  `FUN_0801754A` (5), `FUN_08018A46` (4), `FUN_08016F7C`, `FUN_08017668`,
  `FUN_08009CC4` (4 each);
* `FUN_080052B8` reads register `0x67` (RSSI) for the squelch decision;
* `FUN_080137D4` (with `FUN_08013790`) reads and rewrites `0x33` — the band and
  filter selection — and is called from the RF bring-up itself.
