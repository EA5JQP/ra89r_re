# RA89R Spectrum Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the K1/F4HWN spectrum analyzer screen to the RA89R by importing it as-is, and add a per-spectrum BK4829 / BK4815 / Both choice where Both splits the swept range across the two chips.

**Architecture:** Import `App/app/spectrum.c`/`.h` (fagci/F4HWN) verbatim and add a small, device-free `App/app/spectrum_rf.{c,h}` that owns the chip policy (step→chip, RSSI normalization, setting encode/decode). `spectrum.c` gets the minimum edits to route the sweep/listen RF calls through the selected chip and to add the in-screen setting. Upstream interfaces and signatures are preserved; every deviation is listed here and in `docs/ra89r_spectrum.md`.

**Tech Stack:** C11, PY32F403 register-level drivers, the K1-compatible `BK4819_*` layer (BK4829) plus `bk4815_*` (BK4815), ST7565 panel, host preview and focused C tests.

**Spec:** `docs/superpowers/specs/2026-10-10-spectrum-design.md`

## Global Constraints

- Import upstream verbatim; change only the listed adaptations, and record each in `docs/ra89r_spectrum.md`.
- Keep upstream function signatures and file layout.
- The chip setting is independent of `SetScn` and `TrVfoA`/`TrVfoB`; it affects only the spectrum.
- Persist the chip in `Data[4]` of the spectrum's 8-byte store at EEPROM `0x00A148`; an absent/invalid byte decodes to BK4829.
- `Both` alternates the chip per swept step (BK4829 even index, BK4815 odd); the BK4815 raw RSSI is scaled ×4 into the BK4829's scale.
- Launch is the existing K1 `KEY_5` → `APP_RunSpectrum()` path (F+5); no new launch key.
- Work stays on branch `spectrum`; merge to `develop` only after the radio gate passes.

## Review Focus

1. **Chip = 4815/Both on a range below 134 MHz:** the BK4815's RF role there is unproven — the screen must still run and exit cleanly (a flat trace is acceptable), never hang or crash.
2. **Exit restores receive on both chips:** after leaving the spectrum, the BK4829 registers are restored and the BK4815 is re-applied, so normal receive resumes.
3. **Invalid/absent persisted chip byte:** decodes to BK4829, and the sweep still runs.
4. **Both with an odd step count:** every swept step is measured exactly once (no skipped or duplicated index).
5. **Peak/listen on a Both sweep:** the tune uses the chip that measured the peak.

### Task 2: `spectrum_rf` chip policy and tests

**Files:**
- Create: `firmware/App/app/spectrum_rf.c`, `firmware/App/app/spectrum_rf.h`
- Test: `firmware/tools/test_spectrum.c`
- Modify: `firmware/tools/check_all.sh`

**Interfaces:**
- Produces (device-header free, host-testable):
  - `typedef enum { SPECTRUM_CHIP_4829 = 0, SPECTRUM_CHIP_4815 = 1, SPECTRUM_CHIP_BOTH = 2 } spectrum_chip_t;`
  - `spectrum_chip_t spectrum_rf_step_chip(spectrum_chip_t setting, uint16_t index);` — BOTH: even index → 4829, odd → 4815; otherwise the single chip.
  - `uint16_t spectrum_rf_normalize_rssi(spectrum_chip_t chip, uint16_t raw);` — 4829: `raw`; 4815: `raw * 4` (saturate at `0xFFFF`); BOTH: `raw` (caller passes the already-resolved chip).
  - `uint8_t spectrum_rf_encode_chip(spectrum_chip_t chip);` — 0/1/2, anything else → 0.
  - `spectrum_chip_t spectrum_rf_decode_chip(uint8_t byte);` — 0/1/2 → that value; anything else → `SPECTRUM_CHIP_4829`.

- [ ] **Step 1: Write the failing tests** in `firmware/tools/test_spectrum.c` (a `main` with a `check(ok, name)` helper and a `failures` counter, like `tools/test_scan_dual.c`):

```c
check(spectrum_rf_step_chip(SPECTRUM_CHIP_4829, 0) == SPECTRUM_CHIP_4829, "4829 setting -> 4829");
check(spectrum_rf_step_chip(SPECTRUM_CHIP_4815, 7) == SPECTRUM_CHIP_4815, "4815 setting -> 4815");
check(spectrum_rf_step_chip(SPECTRUM_CHIP_BOTH, 0) == SPECTRUM_CHIP_4829, "Both even -> 4829");
check(spectrum_rf_step_chip(SPECTRUM_CHIP_BOTH, 1) == SPECTRUM_CHIP_4815, "Both odd -> 4815");
check(spectrum_rf_normalize_rssi(SPECTRUM_CHIP_4829, 0x1234) == 0x1234, "4829 rssi unchanged");
check(spectrum_rf_normalize_rssi(SPECTRUM_CHIP_4815, 0x40) == 0x100, "4815 rssi x4");
check(spectrum_rf_normalize_rssi(SPECTRUM_CHIP_4815, 0xFFFF) == 0xFFFF, "4815 rssi saturates");
check(spectrum_rf_decode_chip(spectrum_rf_encode_chip(SPECTRUM_CHIP_BOTH)) == SPECTRUM_CHIP_BOTH, "chip round-trips");
check(spectrum_rf_decode_chip(0xFF) == SPECTRUM_CHIP_4829, "invalid byte -> 4829");
check(spectrum_rf_encode_chip((spectrum_chip_t)9) == 0, "invalid chip -> 0");
```

### Task 3: Wire the chip selection end-to-end

**Files:**
- Modify: `firmware/App/app/spectrum.h`, `firmware/App/app/spectrum.c`

**Interfaces:**
- Consumes: `spectrum_chip_t`, `spectrum_rf_step_chip`, `spectrum_rf_normalize_rssi`, `spectrum_rf_encode_chip`, `spectrum_rf_decode_chip` (Task 2).
- Produces: `SpectrumSettings.chip` (a `spectrum_chip_t`), and a per-operation `static spectrum_chip_t activeChip`.

- [ ] **Step 1: Add the field and includes.** In `spectrum.h`, add `#include "spectrum_rf.h"` and a `spectrum_chip_t chip;` member to `SpectrumSettings`. In `spectrum.c`, add `#include "driver/bk4815.h"`.

- [ ] **Step 2: Persist it.** In `LoadSettings`, after the existing fields, `settings.chip = spectrum_rf_decode_chip(Data[4]);`. In `SaveSettings`, `Data[4] = spectrum_rf_encode_chip(settings.chip);`. Default `settings.chip = SPECTRUM_CHIP_4829` in `ResetSpectrumToDefaults`.

- [ ] **Step 3: Resolve the chip per operation.** Add:
```c
static spectrum_chip_t activeChip = SPECTRUM_CHIP_4829;
static spectrum_chip_t StepChip(uint16_t index) {
    return spectrum_rf_step_chip(settings.chip, index);
}
```
Set `activeChip = StepChip(scanInfo.i);` at the top of `SetFScan` and `GetRssi`; set `activeChip = StepChip(peak.i);` in `TuneToPeak` before `SetF`; set `activeChip = SPECTRUM_CHIP_4829;` in `DeInitSpectrum` before `SetF(initialFreq)`.

- [ ] **Step 4: Branch the RF ops on `activeChip`.** For the BK4815 (`activeChip == SPECTRUM_CHIP_4815`):
  - `SetF`/`SetFScan`: `bk4815_set_frequency(f, false)` and `bk4815_write_reg(0x75, (f >= 28000000u) ? 0x0Au : 0x11u)`; skip the BK4829 register writes.
  - `GetRssi`: `bk4815_read_rssi()` (discard the first read, keep the second) then `spectrum_rf_normalize_rssi(SPECTRUM_CHIP_4815, raw)`.
  - `ToggleAFDAC`/`ToggleAFBit`/`ToggleRX`'s AF: use `bk4815_set_af(on)`; leave the BK4829 calls for the BK4829 chip.
  For the BK4829 path, keep the existing `BK4819_*` code unchanged.

- [ ] **Step 5: Add the in-screen control.** In `HandleUserInput`, in the `kbd.counter == 16` branch (the existing long-press block), add: when `currentState == SPECTRUM && kbd.current == KEY_6`, cycle `settings.chip` 4829 → 4815 → Both → 4829, set `redrawStatus = true`, and return true. Short-press `KEY_6` keeps toggling the listening BW (`OnKeyDownCommon`).
